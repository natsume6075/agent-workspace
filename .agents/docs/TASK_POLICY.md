# タスク管理・引き継ぎポリシー

このワークスペースをCodex等が継続的に利用するための**恒久ルール**。今回のセットアップだけの一時メモではない。

## Source of truth

- ワークスペース横断のタスクとブロッカー: `.agents/docs/TASKS.md`
- 次のセッションの開始地点・環境依存の事実: `.agents/docs/HANDOFF.md`
- 設計変更とその根拠: `.agents/docs/DECISIONS.md`
- 個別プロジェクト固有のタスク: `projects/<slug>/TASKS.md`（必要な時だけ作成し、横断台帳からリンク）
- 導入手順・マシン固有の操作: `setup` のREADME/スクリプト。ここにコピーして二重管理しない。

## 1タスクの必須要素

- 固定ID（例 `ENV-01`）、簡潔な目的
- 状態: `TODO` / `IN_PROGRESS` / `BLOCKED` / `DONE`
- Owner: `human` / `agent` / `joint`
- 明確な完了条件（テストや確認項目）
- 実施証跡（コマンド結果、PR、コミット、ファイル、確認日）
- BLOCKED時のブロッカーと次の一手

## セッション手順

1. 開始時: `AGENTS.md` → `TASKS.md` → `HANDOFF.md` を読み、ブランチとdirty stateを確認。
2. 開始するタスクを `IN_PROGRESS` にし、範囲を絞る。
3. 変更を実施・検証する。本人認証・OSの管理者承認・破壊的変更は人間に委ね、手順を出す。
4. 成功の証跡がある場合のみ `DONE`。実機未検証は `BLOCKED` または `TODO` とする。
5. 終了前: `TASKS.md` と `HANDOFF.md` を更新し、コミットできる内容だけコミット。
6. 新規セッションは会話履歴に依存せず、リポジトリに残る情報だけで再開する。

## 注意

- 完了済みタスクを削除する代わりに簡潔に履歴化し、次の作業を明確にする。
- GitHub上の設定変更もタスクの証跡に含める。
- 新しい仕組みやプラグインを導入する前に「標準機能で十分か」を確認。
- 人間に必要な手順は `setup` に集約してリンクする。会話でしか分からない手順を残さない。
